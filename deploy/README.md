# Выкладка на хостинг и ежедневное обновление рейтинга

## 1. Сборка и загрузка сайта

```
npm run build
```

Перед сборкой автоматически подтягивается свежий рейтинг (`npm run rating`).
Содержимое папки `dist/` загрузите в корень сайта на хостинге (обычно `public_html`).

## 2. Скрипт обновления рейтинга

Загрузите `deploy/update-rating.php` на хостинг **вне папки сайта**, например в домашнюю папку:

```
~/update-rating.php          ← скрипт
~/fabrika.ru/public_html/    ← сайт (тут лежит rating.json)
```

Проверьте вручную по SSH (или через «Запустить сейчас» в планировщике):

```
php ~/update-rating.php ~/fabrika.ru/public_html/rating.json
```

Ожидаемый вывод:

```
[2026-11-13 05:17:02] [rating] 5 ★, 160 оценок, 126 отзывов (было 5, 160 оценок) → /home/.../rating.json
```

## 3. Задача cron (раз в сутки)

Расписание: `17 5 * * *`, то есть каждый день в 05:17. Нечётная минута выбрана, чтобы не совпадать с массовыми задачами в 00:00.

**Beget:** Панель → «CRON» → «Добавить задачу»:

```
/usr/local/bin/php ~/update-rating.php ~/fabrika.ru/public_html/rating.json
```

**Timeweb:** Панель → «Планировщик cron» → «Добавить задачу». Путь к PHP зависит от выбранной версии
(в панели он подсказан, например `/opt/php83/bin/php`):

```
/opt/php83/bin/php ~/update-rating.php ~/fabrika.ru/public_html/rating.json
```

Замените `fabrika.ru/public_html` на реальный путь к вашему сайту.

## Если что-то пошло не так

- Сообщения `блок aggregateRating не найден` или `HTTP 403` означают, что Яндекс показал капчу
  или поменял вёрстку страницы. Сайт продолжит показывать последние полученные цифры.
  Если ошибка повторяется несколько дней подряд, нужно поправить разбор страницы в скрипте.
- `не удалось записать` — у пользователя cron нет прав на запись в папку сайта.
- Не запускайте скрипт чаще пары раз в сутки, иначе Яндекс может начать отвечать капчей.
